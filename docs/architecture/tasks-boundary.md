# Граница задач и операционных разделов ERP

Статус: `current` для реализации этой ветки от `89c790d`, 2026-09-26.
Документ не подтверждает production deploy.

## Контракт

Задачи сохраняют свой интерфейс, историю, исполнителей, сроки, повторения,
календарь и уведомления. Общие вход, сотрудники, назначения ответственных,
«Входящие» и журнал ERP продолжают работать.

TaskStore не разрешает и не хранит новые привязки к товарам, заказам,
продажам, клиентам, ремонтам и закупкам. Старые поля `links`, `entity_type`
и `entity_id` в HTTP payload игнорируются как прочие неизвестные поля;
в ответах нет полей привязки. Удалены обработчики связей, фильтры по типу
объекта, выборка задач объекта и копирование связей при повторении задачи.
Общий поиск объектов `_erp_entity_reference` используется почтой и
назначением ответственных ERP; операции задач его не вызывают.

В других рабочих разделах нет кнопок постановки задач, панелей связанных
задач и соответствующих assets. Эти элементы были удалены ранее; регрессионная
проверка не позволяет вернуть их случайно. Главное меню, общие уведомления
и «Входящие» сохранены. Почта допускает связи с объектами ERP, но не с задачами;
исторические связи с задачами остаются скрыты существующим интерфейсом.

## Сохранность данных и границы изоляции

Миграции и схема базы не изменены. Таблица `task_links` и исторические события
не удаляются: runtime задач больше не читает и не меняет строки этой таблицы.
Валидатор схемы продолжает проверять её наличие для совместимости с текущей
versioned schema. Повторяющиеся задачи создаются без прежних ERP-привязок.

`tasks.db` по-прежнему содержит общие назначения и события «Входящих» других
разделов; её нельзя удалять целиком. Назначения задач продолжают записывать
аудит через существующее подключение каталога. Записи в складские таблицы
при этом не нужны. Эта очистка не создаёт отдельный процесс или физически
изолированную базу и не является гарантией отсутствия любых общих сбоев ERP.

## Проверки

- `tests/test_tasks.py`: устаревшие payload игнорируются; старые строки связей
  и история сохраняются; операции, поиск, календарь, счётчики, повторения и
  удаление работают с запрещённым доступом к строкам `task_links`.
- `tests/test_tasks_api.py`: жизненный цикл задачи под SQLite authorizer,
  запрещающим INSERT/UPDATE/DELETE во все таблицы каталога, кроме журнала
  и служебного счётчика SQLite; сравнение данных до/после; запрет вызова
  общего поиска ERP из обновления задачи и игнорирование старых фильтров.
- `tests/test_tasks_standalone.py`: отсутствие кнопок/панелей связей в других
  разделах и старых assets.
- `tests/test_collaboration*.py`, `tests/test_mail_web.py`: общие назначения,
  «Входящие» и привязка почты к заказу сохраняют поведение.

На Windows используется локальный адаптер по образцу `scripts/test_services.py`:
временные базы, отключённая внешняя сеть и однопроцессный shim `fcntl`.
Такой запуск проверяет прикладное поведение, но не POSIX-блокировки;
он не заменяет Linux CI перед публикацией.
