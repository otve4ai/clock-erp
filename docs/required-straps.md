# Обязательный ремешок для корпуса

Статус: current для реализации в этой ветке; не подтверждает deploy.

В карточке товара администратор включает «Требуется ремешок». Настройка
сохраняется сразу, отдельно от остальных полей карточки, с записью в журнал.
Сотрудник видит настройку, но не может менять её ни в интерфейсе, ни через API.
Существующие товары по умолчанию не отмечены. Автоматического определения по
названию или массового включения для бренда нет.

В окне проведения заказа для каждой отмеченной позиции появляется обязательный
выбор ремешка из соответствующих категорий. Корпус задаётся сопоставлением
позиции заказа, количества корпуса и ремешка равны количеству заказанных часов.
Для обычных товаров дополнительного поля нет. Фиксированный состав и признак
обязательного ремешка нельзя включить одновременно.

Сервер проверяет признак, категорию, активность, складские блокировки и остатки
в транзакции продажи. При нехватке любого компонента откатывается весь заказ.
Коммерческая строка и её цена сохраняются в одном экземпляре. Отдельной
коммерческой строки ремешка нет; две складские строки и их снимки привязаны к
исходной строке продажи. Поддерживаются несколько корпусов в одном заказе и
совместное использование одного ремешка несколькими позициями.

Повторное проведение не списывает повторно. Отмена и возврат используют
исторические движения и снимки, даже если администратор позже выключил признак.
Физические остатки компонентов, если они уже заведены, учитываются существующим
механизмом ComponentInventory; признак не создаёт и не меняет остатки сам.
Операция старой «Замены ремешка» не может обойти обязательный выбор.
Прямая ручная продажа отмеченного корпуса без состава блокируется: его нужно
проводить из заказа с выбранным ремешком.

Миграция `2026-09-24-required-straps-v1` добавляет только таблицу настроек
`erp_required_straps`. Она запускается штатным deploy-runner, не из HTTP-запроса.
Старые настройки, суммы и движения не переписываются. Перед deploy нужен
штатный backup; откат версии со схемой — по стандартному согласованному backup.

Проверки: `tests/test_required_straps.py`, существующие тесты проведения заказов,
составов, WB и миграций. В локальной Windows-проверке fcntl подменяется по образцу
`scripts/test_services.py`; межпроцессные блокировки проверяет Linux CI.
