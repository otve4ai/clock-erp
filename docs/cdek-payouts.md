# Выплаты СДЭК

Статус: реализовано локально, ещё не опубликовано. Самостоятельный модуль
`/app/analytics/cdek-payouts`; аналитика содержит только ссылку. Шаблон, CSS,
JS, сервис, снимок и расписание независимы от BusinessAnalytics.

## Расчёт

- Суммы считаются Decimal в рублях. Другие валюты требуют отдельной сверки.
- «Ждём перечисления»: payment_sum получен, сумма payment_sum в оплаченных
  реестрах меньше полученной. Охват реестров должен включать дату вручения.
- «Ждём покупателя»: положительный НП, нет полученной оплаты и терминального
  отказа/возврата. Долгое ожидание само по себе не означает отказ.
- Возвратные/обратные отправления не создают повторный наложенный платёж.
- Частичный выкуп считается по фактическому payment_sum. Наличие услуги
  PART_DELIV не означает, что выкуп был частичным.
- «Перечислено»: покрыта фактически полученная оплата; показывается transfer_sum
  после удержаний. Дата — payment_date реестра, не дата создания реестра.
  Банковская выписка не проверяется.
- Отсутствие суммы при вручённом заказе с НП, другая валюта, недостаточная
  история или противоречие сумм дают «Не проверено», а не нулевой долг.
- Оценка к перечислению вычитает текущие расходы накладной только при полном
  отсутствии перечислений. Это не окончательное сальдо взаиморасчётов.

API `/registries?date=YYYY-MM-DD` возвращает `{}` в дни без реестров.
Непустые ответы проверяются: структура, денежные значения, дата оплаты.
Совпадающие реестры дедуплицируются, конфликтующие прерывают обновление.

## Источники и охват

Номера поступают из канонических продаж ERP, кеша доставки, реестров и
импорта XLSX «Отчёт заказов» СДЭК. Чтение отдельной накладной не обеспечивает
полный перечень договора. Экран всегда показывает ограничение полноты.
Импорт сохраняет только номера и начальную дату, без контактов получателей.
Лимиты: 10 МБ / 10 000 строк, распакованный XLSX до 40 МБ.
Реальные данные, отчёты и ключи в Git не включаются.

Первый проход покрывает 45 календарных дней включительно. Импорт более раннего
отчёта расширяет историю (максимум два года). Ранее найденные номера сохраняются.
GET экрана и статуса не вызывает API СДЭК. Фильтры меняют отображение, а не
период фоновой проверки. Состояние задолженности всегда на момент снимка.
Фильтр даты перечисления выбирает записи реестра по дате, включая частичные
перечисления в разные дни. Вкладка реестров фильтруется по дате оплаты,
показывает полные суммы, включая накладные вне периода создания.

## Обновление и установка

Web использует `CDEK_PAYOUTS_DIR` или `CDEK_CACHE_DIR/payouts`. Каталог должен
быть общим и постоянным для web/CLI. Отдельный CdekSync обеспечивает общий
межпроцессный lock, фоновые ручные запросы и защиту повторного запуска 60 с.
POST защищён существующими правами просмотра заказов и CSRF.

Пакет ограничен 100 запросами / 150 секундами плюс текущий HTTP-запрос.
Стадия сохраняется атомарно после каждого запроса, следующий пакет продолжает
её. Публикуется только завершённый снимок; ошибка связи сохраняет прежний
снимок и показывает ошибку. Пропавшие накладные помечаются непроверенными,
первые неуспешные поиски перечислены в предупреждении. Незавершённая стадия продолжается и после смены календарного дня.
Снимок старше 24 часов помечается устаревшим.

CLI: `python -m scripts.cdek_payouts_sync`. Отдельные units:
`deploy/systemd/vechasu-cdek-payouts.service` и `.timer`, ежедневно в 06:00 по времени сервера. Для systemd 219 часовой пояс сервера должен быть Europe/Moscow; это проверяется перед установкой. Таймер доставки не меняется.
Перед установкой проверить EnvironmentFile, постоянный CDEK_PAYOUTS_DIR,
резервную копию, права и реальные пути. Установка — отдельный deploy.
После проверки установленного таймера установить `clock-erp-cdek-payouts.conf`
в drop-in каталог web-сервиса. Он задаёт `CDEK_PAYOUTS_TIMER_ENABLED=1` и
общий с CLI каталог `/opt/clock-erp/instance/cdek/payouts`. До этого интерфейс не утверждает, что расписание
активно. Обновление кода само по себе не устанавливает и не запускает job.
Первичное наполнение: загрузить полный отчёт за период, выполнить пакеты
до появления полного снимка. CLI выполняет до трёх пакетов за утренний запуск.
Если не успел, продолжит со следующего запуска; ручная кнопка доступна всегда.

Откат: отключить только новый таймер, вернуть предыдущий release. Каталог
выплат можно сохранить. Складские данные и заказы модуль не изменяет.

## Проверка

`python -m unittest discover -s tests -p 'test_cdek*.py'` с тестовыми клиентами
и временными каталогами. Проверяются частичная оплата/перечисление, возвраты,
валюты, неполный охват, фильтры, сохранение снимка при сбое, возобновление,
права, CSRF, XLSX и Flask-шаблон. Реальные API во время тестов не вызываются.
