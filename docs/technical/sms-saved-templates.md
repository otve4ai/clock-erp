# Сохранённые SMS-шаблоны

Статус: draft (реализовано в рабочей ветке, публикация не подтверждена).

Единственный источник текста — `sms_templates.message_text` в разделе
«SMS → Шаблоны». Предпросмотр (`POST /api/v1/sms/templates/preview`) и отправка
читают актуальный активный шаблон по ID через `SmsStore.render_saved_template`.
Правка карточки применяется к следующим отправкам; выключенный шаблон недоступен.
Для будущего фонового задания применяется тот же метод с серверными данными
заказа. Эта правка не запускает расписание 3/5/7 и не отправляет сообщения.

`{tracking_number}` и `{Накладная}` равнозначны. Значение берётся из снимка
выбранного заказа существующим `get_order_tracking`, а не из браузерного payload.
Если в снимке накладная отсутствует, используется единственная накладная связанных продаж Tictactoy с тем же номером заказа. Повторяющиеся товарные строки объединяются; разные накладные, отсутствие или некорректный номер блокируют предпросмотр и отправку.
`{client_name}` получает `first_name` либо поле `customer` исходного заказа.
ФИО не разбирается эвристически: если источник содержит полное имя, оно сохраняется.
Без имени начальное обращение с запятой убирается.

Текст выбранного шаблона в форме доступен только для чтения. Для произвольного
текста нужно выбрать «Без шаблона». Незаполненные фигурные переменные блокируются
также на уровне сервиса отправки. При смене получателя выбранные связи сбрасываются;
устаревший асинхронный ответ не заменяет свежий предпросмотр.

## Выбор заказа для ручного SMS

Основной сценарий формы: поиск по номеру заказа → выбор результата → телефон
из заказа → предпросмотр → отправка. `GET /api/v1/sms/orders?q=...` ищет
в локальном снимке по номеру, не требует записи клиента и возвращает до 20
результатов с точным совпадением первым. Ведущие нули сохраняются. Для выбора
используется внутренний ID заказа; номер остаётся отображаемым значением.

Имя берётся из `first_name` / `customer` заказа и не обязательно. Если телефон
отсутствует, его вводят вручную. Редактирование номера, смена или снятие заказа
сбрасывает предыдущего получателя. Просроченные ответы поиска игнорируются,
ошибки видны в форме. Выбор по клиенту, выбор связанного ремонта и скрытая передача ID ремонта удалены из формы.
Открытие формы из заказа также не требует предварительной связи с реестром клиентов.
Предпросмотр показывает телефон получателя; имя подставляется автоматически и доступно для ручной правки.

Проверки этого сценария: `tests.test_sms` и `node --test tests/test_sms_compose.cjs`.
Изменение формы подготовлено локально; публикация и проверка production не выполнены.

## Включение существующего шаблона

После публикации кода открыть «СДЭК — ожидает получения», включить «Активен»
и сохранить. Переписывать текст или создавать дубликат не нужно: русская переменная
из уже сохранённой карточки поддерживается. Включение шаблона само по себе
не запускает рассылку. Проверить предпросмотр на заказе с накладной; реальные
тестовые сообщения отправлять только на согласованный пользователем номер.

Проверки: `tests.test_sms` (временные БД, подменённый провайдер). На Windows
Linux `fcntl.flock` подменяется только в тестовом процессе; межпроцессная
Linux-блокировка таким запуском не проверяется.

## Прямой поиск СДЭК

Поле «Номер заказа или накладной СДЭК» сохраняет поиск заказов ERP.
Для полного числового номера (6–20 цифр) доступна кнопка «Найти отправление
в СДЭК». GET /api/v1/sms/cdek запрашивает существующим клиентом СДЭК отправление
по cdek_number; заказ в ERP не требуется. Телефон берётся только из recipient.phones,
имя — из recipient.name. Один уникальный корректный телефон подставляется;
при отсутствии или нескольких телефонах требуется ручной ввод.

Данные выбранного отправления хранятся в серверной сессии 30 минут, максимум
пять выборов. Предпросмотр и отправка шаблона используют сохранённую накладную
и автоматическое имя; явная ручная правка имени имеет приоритет. Выбор СДЭК несовместим с одновременно выбранным заказом
ERP/клиентом/ремонтом; изменение поискового номера сбрасывает выбор и телефон.
Номер магазина из СДЭК не превращается в ссылку на несуществующий заказ ERP.
Локальный предпросмотр использует только тестовую накладную 1234567890;
реальные ключи, запросы СДЭК и отправка SMS в нём не используются.

Имя получателя можно изменить вручную или очистить после автоподстановки. Явное поле recipient_name_override имеет приоритет в предпросмотре и отправке, в том числе пустое значение; выбор другого заказа/СДЭК сбрасывает ручную правку. Исходный заказ и данные СДЭК не изменяются.

Поиск номера реализован в `app/services/sms_order_search.py` как чтение существующего снимка заказов. Схема БД и Recovery V2 contract не меняются; модуль схемы `orders_snapshot.py` для SMS не изменяется.

Локальная правка подсказки: ошибка заполнения шаблона показывается над текстом SMS. При нехватке данных для автозаполнения подсказка универсально объясняет ручную отправку через «Без шаблона» и проверку текста и телефона получателя. Выбор шаблона по-прежнему требует корректной накладной.
